## 四、去重规则

1. 同一事件只由一个刊物刊登完整报道，归属见 [`editorial/README.md`](../editorial/README.md) 第 1.1 节。
2. **事件编号** = 完整报道的本站链接：`https://rich-richer.github.io/p/<刊物 ID>/?date=<日期>#<条目 id>`。
3. 写稿前查重：`node automation/find-event.mjs <关键词或来源链接>`。
4. 出刊脚本自动检查：最近 14 天内，不同刊物共用同一外部来源、且双方都没有链接到对方的，整批中止并提示应加入的本站链接。同一刊物跨期引用同一数据页（天气、行情历史）不算重复。

## 2026-10-01 出刊过程中发现的问题（待 AIggy 决定）

9/28、10/1 两次出刊（含子任务并行写稿）过程中实际遇到、需要人工决定或留意的问题，按影响排序：

1. **并行出刊没有防重复机制**：10/1 要求「出刊今天的」时，发现另一次交互式会话已抢先发布了当天 daily-news、finance-crypto、ai-architecture、ai-safety、people-watch 五份刊物；这次靠出刊前主动 `git log` 核对才避免重复出刊或推送冲突，但仓库里没有任何「今日已出刊清单」或锁文件去自动防止两个并行会话同时对同一天同一刊物跑 `publish.mjs --push`。**建议**：出刊前固定先跑 `git fetch && git log --oneline -10` 核对，或考虑加一个轻量的「出刊中」标记文件。
2. **改版可能发生在当前会话不知情的时段**：9/30 深夜发生的第二次改版（9 刊重构）, 10/1 开始工作时完全没有提示，是靠重新读 `editorial/README.md` 和 `git log` 才发现，此前准备下发给子任务的指令是按旧结构写的。**建议**：以后任何一次出刊开始前，固定把「检查 git log 是否有本会话不知情的改版提交」当成前置步骤写进 README 第 2 节，不要默认沿用对话历史里的认知。
3. **跨会话对同一期内容的记忆会过期**：9/28 给 education-weekly 子任务下达「昨天只出了 2 条」的任务背景时，这个信息已经过期——9/27 晚间另一次会话已把该期补齐到 14 条。子任务自己发现了矛盾并指出，这次没有造成实际问题，但说明「我上次做过这个」不能代替「出刊前重新看一眼当前文件」。
4. **辽宁板块连续三期（9/27、9/28、10/1）只能凑到 1–2 条，低于手册建议的 3 条**：不是单次意外，是重复模式。「最近 30 天内未报道过」的窗口 + 每周两期的频率，可能让「每期 3 条」在源头上就偏高。**建议**：考虑放宽辽宁窗口、降低建议条数，或接受辽宁板块本来就该比海外/中国薄。
5. **「本周无实质更新不出刊」与新增的硬性「经典论文回顾」要求字面上有冲突**：`ai-architecture.md` 仍写「本周确无实质更新时不出刊」，但 `layout.json` 把「经典论文回顾」设为每期硬性必出（这个板块本质是常设科普栏目，不依赖本周是否有新闻）。9/28 那期是我在任务指示里主动替子任务定了调（仍出刊、经典回顾兜底），手册原文没讲清楚这个优先级，不同执行者可能做出不同选择。**建议**：在 `ai-architecture.md` 里明确「只要经典论文回顾能凑出 1 条，就不算'无实质更新'，仍要出刊」。
6. **跨刊占位链接依赖主会话手工对账**：并行子任务写「事件已被主刊完整报道」的条目时，互相看不到对方最终用的条目 id，只能先用原始来源占位，由主会话在出刊前手动核对补上本站链接（9/28 用了 2 次，10/1 没有用到，均顺利处理）。条目数增多时这一步容易漏改，导致预检反复中止重试。**建议**：暂无自动化方案，目前只能主会话出刊前逐条核对。
7. **「同一通用榜单页面被多条引用」没有明确规则**：10/1 topic-radar 子任务自己想出变通——微博热搜榜首页链接只正式挂在一条的 `sources` 里，其余条目的排名数据写进正文、不作为 `sources` 对象引用，以规避「同一期内来源 URL 不能重复」的限制。这个变通可用，但说明规则对这种常见情况（同一榜单页面是多条热点共同的证据来源）没有明确豁免。
8. **WebSearch 工具有单会话调用次数上限，用尽后退化检索质量**：10/1 compute-intel 子任务报告 WebSearch 触达约 200 次调用上限后改用 `automation/fetch.py` 直连抓取，但百度/必应等页面反爬导致返回无关内容，可能影响了辽宁第三条动向的检索深度。记录下来是为了避免以后把「检索工具用尽」误判成「确实没有可靠新闻」。

以上均为流程观察，**不涉及已发布内容的事实错误**，不需要按第 11 节勘误处理。

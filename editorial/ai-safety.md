# AI 安全公开动态（ai-safety）

先读 [`README.md`](./README.md)。本手册只写这份刊物的特有规则。

- 建议频率：每周三。窗口：过去 7 天。
- 主题：**公开的** AI 安全与滥用防范新闻。分析师语气。
- **2026-09-27 改版**：深化漏洞、提示词注入（prompt injection）、越狱（jailbreak）研究、安全研究者与相关组织动态、厂商回应和修复状态。本刊负责这些事件的**技术分析**；双语每日新闻「AI 安全观察」只写短讯，本刊已有完整报道时它会链接过来。
- 使用 AIHOT：否。

## 关键范围限制（硬性）

可以写：漏洞与提示词注入的披露、越狱研究的**存在和影响**、研究者与组织的公开发布、厂商回应和修复状态、政策、厂商风险框架（preparedness frameworks）、防御工具、负责任披露（responsible disclosure）。每条只写「谁、何时、影响什么产品或场景、厂商如何回应、目前修复状态」。

**不得**包含越狱提示词、攻击载荷、漏洞利用步骤、绕过方法，或来自越狱社区的操作教程；引用研究时只写结论和影响，不复述可复现的方法。

每条在 summary 开头标明**证据等级**，三选一：

- 【研究演示】研究者或红队在受控环境中演示，尚无实际受害记录；
- 【已确认漏洞】厂商或权威机构确认存在，写明是否已修复；
- 【已发现实际利用】已有真实攻击或受害案例，写明范围和出处。

并写明**修复状态**：已修复 / 修复中 / 厂商未回应 / 不适用。

## 条目安排

- 共 3–8 条符合范围的条目，不凑数。`category`：`漏洞与提示词注入` / `越狱研究` / `研究者与组织` / `厂商回应与修复` / `政策监管` / `厂商框架` / `防御工具`。
- **每期都有监测结论**：`lead` 的 `summary` 以「本周监测结论：」开头，用一两句话概括本周全局，并逐项说明漏洞、提示词注入、越狱研究、厂商修复四类中**哪几类本周没有可信新动态**（直接写「本周无可信新披露」，不编造更新）。
- 四类都没有可信新动态、政策与框架也无新进展时，本期不出，在报告中说明「本周无可信新动态」。
- `important` 2 条。
- 英文来源填 `originalTitle`，头条尽量附 2 个以上来源，让原标题在来源面板中显示（规则见 README 第 4 节）。
